# Receipt scoring test plan and traceability

**Owner:** Sihao Liu · **Scope:** Python `receipt-v1` models, target math,
deterministic scorer, and `POST /receipt/rank`

This plan starts from the P2 requirements and maps each rule to evidence at more
than one test level. A passing count alone is not treated as proof: fixed answers,
independent oracles, source mutations, and a real HTTP process exercise different
failure modes.

## Requirement-to-test matrix

| Requirement / failure to prevent | Unit and fixed-answer evidence | Broader evidence |
|---|---|---|
| Pure scorer; no network, DB, Gemini, or implicit clock | explicit `as_of_date`; invalid dates rejected | TestClient and live Uvicorn both run after Gemini/Supabase variables are removed |
| Ingredient matching and duplicate inventory rows | hand-computed golden case; cross-location quantities sum | 150 randomized inventory cases compared with an independent oracle |
| Expired stock is unusable; stock expiring today is usable | mixed expired/usable rows; exact date boundary | mutation changes `>=` to `>` and is killed |
| Expiry window is days 0–3 inclusive | explicit day 3/day 4 test | mutation changes `<= 3` to `< 3` and is killed |
| Missing or incompatible units are unresolved | null and `kg` versus required `g` cases | randomized units plus mutation that ignores unit equality |
| `servings` scales requirements only | two-serving fixed case | differential oracle multiplies the requirement independently |
| Null requirement is unknown; zero remains zero | golden case and validation boundaries | randomized null/zero requirements; M0 detects the planted zero-to-100 defect |
| Negative/non-finite quantities and invalid dates fail clearly | model validation parametrization | API and live HTTP assert structured `422` responses |
| Inventory, expiry, nutrition and total remain auditable | line/subtotal sum test; hand receipt | M0 validates both sums; expiry-sign mutation is killed |
| Scores are ranking points, not percentages | API asserts `rank_score` and absence of `match_score` | Feiyang UI review confirms the value is labelled “ranking points” |
| Ties use ascending `recipe_id` | fixed tie and arbitrary unique ID properties | mutation reverses the tie key and is killed |
| Input ordering cannot change output | Hypothesis inventory permutations | M0 performs 20 seeded shuffles |
| Remaining and overage are both preserved | fixed partial/full/over-target cases | 150 randomized target cases against an independent oracle; reversed-overage mutation is killed |
| Missing nutrient data is not zero | missing recipe and missing consumed cases | randomized optional inputs; `or`→`and` mutation is killed |
| Decimal rounding is half-up once at the end | `2.675` and mutation witness at `2.685` | half-even replacement mutation is killed |
| Internal gateway token is enforced when configured | TestClient missing/wrong/correct token | live Uvicorn repeats missing/wrong/correct-token behavior over TCP |
| Same request produces the same response | deterministic fixed output | two identical real HTTP requests return identical bodies |
| Legacy endpoints remain available | lazy-import unit/API behavior | 33 legacy inventory-recommend tests pass; real Gemini test is skipped without a key |

## Test levels

### Unit and component tests

- strict Pydantic contract and invalid-input behavior;
- target remainder, overage, completeness, scoring, and half-up rounding;
- inventory aggregation, units, expiry, servings, warnings, subtotals and ties;
- independent hand-computed receipt, not an expectation generated by the scorer.

### Integration tests

`test_api.py` calls the complete FastAPI route through `TestClient`, including
request parsing, dependency authentication, response-model serialization and
error responses. It also confirms that global nutrition warnings do not serialize
a fake ingredient ID.

### System tests

`test_system_http.py` starts a separate Uvicorn process with no Gemini or Supabase
credentials, then talks to it through a real loopback TCP connection. It covers
authentication, the golden ranking, invalid input and repeated-request stability.
The subprocess is always terminated in fixture cleanup.

### Property and differential tests

- Inventory order permutations always produce structurally identical model output.
- Arbitrary all-tie recipe sets always sort by ascending recipe ID.
- Target outcomes never expose a negative remainder or overage.
- 150 generated inventory cases are compared against a small reference algorithm
  that calls no production scoring helper.
- 150 generated nutrient cases are compared against separate reference math.

### Mutation tests

`test_mutations.py` creates nine in-memory source mutants. Each witness must first
pass on production code, then fail or raise for the mutant. No production file is
rewritten, and no additional package is required.

The killed mutations are:

1. expiration on `as_of_date` becomes expired;
2. exact quantity coverage no longer counts;
3. inventory units are ignored;
4. ties prefer the higher recipe ID;
5. expiry day three is excluded;
6. expiry points are subtracted;
7. one missing nutrient source is treated as complete;
8. overage subtraction is reversed;
9. half-up rounding becomes half-even.

Current result: **9/9 seeded mutants killed**. This is targeted mutation evidence,
not a claim that every possible syntax mutation has been generated.

## Coverage statement and remaining limits

The environment does not currently include `coverage.py`/`pytest-cov`, and dependency
and CI configuration belong to Wenbo. Python's standard-library `trace` was used as
an auxiliary execution check, but its summary is not presented as formal branch
coverage. No unsupported percentage is claimed.

Remaining external coverage is intentionally separate:

- the scorer has no database or Gemini dependency, so those systems are not part of
  its system boundary;
- the system test proves a local production-style ASGI process, not a deployed Vercel
  or Render environment;
- the frozen ranking request has no recipe nutrient-total field, so the API can only
  exercise the explicit `incomplete` nutrition path. Complete nutrient calculations
  are nevertheless unit-, property-, differential-, and mutation-tested directly.
